# Connectors

Connectors expose data that already lives in a Fabric item. Run `npx rayfin connector types --json` for the live
catalog (types, operations, auth, package names and versions); do not trust a version printed in an old doc.

## Pick the type
| Item | Type | Ops | Category |
|---|---|---|---|
| Lakehouse SQL analytics endpoint | `fabric-sqlanalytics` | read | A (entities, typed CRUD, `@role` policies) |
| Warehouse | `fabric-warehouse` | read/create/update/delete | A |
| Fabric SQL database | `fabric-sqldatabase` | CRUD | A |
| Power BI semantic model | `fabric-semanticmodel` | `executeQuery` (DAX) | B (function bridge: named operation, no entities) |
| KQL / Eventhouse | `kusto` | held in 1.36.2 | B |

- Category A: generated entity files + metadata.json; row-level `@role` policies apply. Category B: a raw DAX/KQL string, no Rayfin row security; the source enforces its own. Read ONE category's doc, not both.
- Kusto: if the user asks for a KQL database and the project does not already declare it, say authoring is held and stop; do not substitute another source. Exact refusal: `Connector type "kusto" is not available in this release. Supported types: [fabric-sqlanalytics, fabric-warehouse, fabric-sqldatabase, fabric-semanticmodel].`
- OneLake files (`Files/`, parquet, PDFs) are not reachable through connectors: use a function with `AudienceType.Storage`.

## Authentication
- Category A `connector add` writes `auth.type: application` in 1.36 (the Learn page still shows `delegated`: stale). Application means every user sees whatever the app identity (the item owner) can see. Set `delegated` explicitly when the source must enforce per-user access, and re-apply it after any re-run of `connector add` (it rewrites the default). On a service-principal-owned item Category A reads fail with 401 under either mode (#93).
- Category B (semantic model, kusto) MUST be `delegated`; `rayfin up` rejects `application`. Omitting `auth.type` is a validation error.

## Workflow
1. `connector search [q] --workspace-id <ws> --type <t> [--json]` to get ids (`--type` is mandatory with scoped search).
2. `connector add --type <t> --workspace-id <ws> --item-id <item> --name <n> [--operations read,...]`. Literal ids only. Narrow `--operations` to what was asked (read-only -> `read`); you can narrow below the catalog default, never widen. Entries in rayfin.yml are `- name: read` objects, not bare strings. Run the printed pinned install command verbatim (npm `latest`/`preview` tags lag and pull a second Rayfin line, giving type errors).
3. Preflight with one query before any UI: Category A `connector inspect --name N --entity E --rows 1` (`--entity` takes the TABLE name, `--rows` <= 100); semantic model `connector invoke N executeQuery --file probe.query.json`. Failure = connector/permission/platform problem: report it and stop.
4. `npx rayfin up` (connectors do not run under `rayfin dev`; `connector invoke` on a semantic model is the exception). `npx rayfin up connector apply [--name N]` re-applies connector config only (Preview).
5. Prove it in the deployed app with a non-owner user. CLI probes run under your own identity.

## Hand-edits and removal
- Category B `schema.ts` is `// @generated - do not edit`; it is regenerated by `connector remove` + `add`. Category A `schema.ts` has no banner: it is yours to overwrite with an aggregate. Remove the `@generated` marker before hand-authoring; never re-run `add --yes` afterwards.
- `connector remove` deletes the yml entry AND the whole `rayfin/connectors/<name>/` directory: back up hand-made entities first.
- Reserved GraphQL names: an entity named `Date` etc. is rejected ("Reserved GraphQL type names detected"); rename the class and keep `Source({table:'...'})`.

## Client wiring (Category B)
`new ConnectorsRayfinClient(config, { <name>: fabricSemanticModel() })`: the runtime map (second argument) is required for semantic model (Arrow decode) and kusto (routing). Result handling is in data-apps-semantic-model.md.

## Other traps
- `SELECTION_REQUIRED`: `.where/.orderBy/.first` need `.select([...])`; `findMany/findFirst/findByKey` need the entity class registered (as a value, re-exported) in `connectorConfig.entities`.
- `FEATURE_NOT_ENABLED` / 404 on `/connector-invoke/<name>`: the workspace-level ConnectorFunction switch is off; not fixable in the app; escalate for workspace enablement.
- `Access token has the wrong audience for the Power BI query API`: `RAYFIN_TOKEN` carries a wrong-audience token, or `--json` was used before Power BI consent; unset the token or drop `--json`.
- `--transport deployed` needs an app-session token in `RAYFIN_TOKEN`; `rayfin login` cannot mint it. Avoid; test through the app.
- Discovery warning at `add` is best effort (connector still written, exit 0): read `reason` (permission/login/auth/unknown), fix access, re-run.
- `connector invoke` output over 8 KB spills to a file with a preview (kept 14 days / 20 files); `--max-inline-bytes 0` prints everything.
