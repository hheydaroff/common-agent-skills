# Ecosystem: what exists, what to reuse, what not to duplicate

## Microsoft's own Rayfin agent assets
- `microsoft/rayfin` (MIT) ships a getting-started skill: Claude Code `/plugin marketplace add microsoft/rayfin` then `/plugin install rayfin@rayfin-skills`; Copilot CLI `copilot plugin marketplace add microsoft/rayfin`; Codex `codex plugin marketplace add microsoft/rayfin`; Gemini `gemini extensions install https://github.com/microsoft/rayfin`; cross-agent `npx plugins add microsoft/rayfin`. It only gets you into a project, then hands off to the in-project skill. Guided prompt: fetch `https://aka.ms/rayfin/start.md` with your web-fetch tool or `curl -sSfL`.
- In-project, version-locked skills (generated by `rayfin init`): `rayfin`, `rayfin-functions`, `rayfin-connectors`, `rayfin-storage`; the `universal-app` template adds `capability-router`, `analytics`, `visuals`, `query-design`, `dax-authoring`, `schema-discovery`, `fabric-sdk`, `connectors`, `data-modeling`, `crud-ui`, `functions-capability`, `external-api-workflows`, `fabric-data-agent`, `app-design`, `app-validation`, `app-deployment`. When these exist in the project, they win over this skill on version-specific detail.
- `npx rayfin docs search|discover|get --module guide --path <p>` and the optional `rayfin` MCP server (`search_docs`, `get_doc`, `discover_packages`).
- Official docs: learn.microsoft.com/fabric/apps/ (create-app-with-cli, create-app, deploy-app, data-apps-template, connectors, overview, project-structure); rayfin.ai/docs. Learn pages lag the CLI (connector auth default, where deploy state lives, `VITE_FABRIC_*` source): prefer the installed guide.

## Lineages inside Microsoft's samples
- `dataapp` sample (older): `@microsoft/fabric-app-data`, `npx fabric-app-data`, `fabric.yaml`, embedded-only, Playwright against the portal embed.
- `universal-app` (newer): Rayfin connector, capability packs, standalone and embedded. Prefer it; keep the older sample's rules only where the newer lacks them.
- Packages: `@microsoft/fabric-visuals`, `@microsoft/fabric-datagrid`, `@microsoft/fabric-app-data` + `-embed-client` + `-proxy`, `@microsoft/fabric-user-data-functions`, `@microsoft/rayfin-{core,client,data,auth,lib,embed-host,app-state-fabric,local-dev,auth-provider-fabric,connector-fabric-semanticmodel}`.

## skills-for-fabric (microsoft/skills-for-fabric): neighbours, not substitutes
It has ZERO coverage of Rayfin, AppBackend or the app item type. Cite it for artifacts around the app and stop there.
| Need | Skill there |
|---|---|
| Build or modify the model an app queries (TMDL, Direct Lake binding, field parameters, DAX performance, `INFO.VIEW.*` discovery) | `semantic-model-authoring` (tool priority: `powerbi-modeling-mcp` first; else TMDL round trip `getDefinition` -> edit -> `updateDefinition`) |
| NL-to-DAX against a model; `ValueSearch` before filtering on a named entity; `ExecuteQuery` default 250 / max 1,000 rows | `fabriciq` |
| PBIR/PBIP report lifecycle; a report `DataFunction` button can call a published User Data Function | `powerbi-report-cli` |
| Catalog governance and item discovery | `onelake-catalog-cli`, `search-consumption-cli` (admin APIs 401/403 non-tenant-admins) |
| Dev -> test -> prod | `deployment-pipelines-authoring-cli` (deploy is an LRO; no REST for deployment/parameter rules; app item type not listed) |
| Git integration | `git-integration-operations-cli` (`updateFromGit` needs the current `workspaceHead` else `400 WorkspaceHeadMismatch`) |
| Per-stage config for UDFs | `variable-library-cli` (booleans arrive as strings: `str(v).lower()=="true"`, never `bool(v)`) |
Conventions when using them: Fabric REST calls carry header `x-ms-fabric-skill: <skill>`; `az rest` needs `--resource https://api.fabric.microsoft.com` or 401. Install: `/plugin marketplace add microsoft/skills-for-fabric`, `/plugin install fabric-skills@fabric-collection`. Its `FabricAppDev` agent and `DashboardApp` prompt build bring-your-own apps (Python, ODBC/XMLA), not Fabric-hosted ones.

## Community templates (microsoft/awesome-rayfin): what each is the best reference for
`npm create @microsoft/rayfin -- --template https://github.com/microsoft/awesome-rayfin`
| Template | Read it for |
|---|---|
| fabric-atlas | snapshot publication with manifest-last, typed functions with app identity, sentinel gate, `sub` policies, platform-gaps doc, UUID idempotency, chunking |
| pbi-fixer | Python User Data Functions as a server proxy, MSAL silent/click-gated sign-in in the portal iframe, server LRO resolver (two 202 shapes), UDF envelope client |
| semantic-directory | demo/live seam, `INFO.VIEW.*` discovery, batched value probes, size budget, official `fabric-app-data` packages |
| finance-analytics | config-driven shell, DAX push-down, real xlsx/CSV/PPTX export, deterministic insights, accessibility tests |
| helsinki-public-transport | Eventhouse DirectQuery semantic model, three transports with fallback, host `postMessage` bridge, poll-after-response |
| campus-scheduler | provenance stamps, fail-closed release lever, `verify_publishable`, persisted state across scale-to-zero |
| field-technician | Docker local dev, role-based UI (copy the UI, not the access model) |
| universal-app | embedded skills, capability router, idempotent pack mechanism, headless chart preview |
Gallery CI only lints/builds/tests templates touched in the diff, so an old template can rot; run its own lint/build/test before reuse. Template packaging rules are in rayfin-project.md.

## Method: embedded skills and pack mechanism (universal-app)
`AGENTS.md` -> `capability-router` skill -> capability packs; `npm run pack:add -- analytics` applies `pack.json` (service flags in rayfin.yml, pinned deps, kit files, seed files) idempotently with `--dry-run`, `--no-install`, `--force-seeds`. `match:@microsoft/rayfin-core` pins sibling Rayfin packages to one version (literal pins skew a release later and give cross-package type errors). Seed files are replaced only if their sha256 is in `seedReplaceIfPristine`; a substring key was abandoned because it silently overwrote an auth-guarded `App.tsx`. `npm test` fails printing the expected digest when a base starter changes.
